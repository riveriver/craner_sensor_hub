# Modbus RTU 通信时间参考：4800 / 9600 / 115200

## 1. 这份文档说明什么

本文用于估算 Modbus RTU 读取 Holding Register 的理论通信时间，帮助设置 `rx_timeout`、轮询周期和调试超时问题。

这里按当前工程常用串口格式计算：

| 项目 | 值 |
| --- | --- |
| 串口格式 | `8E1` |
| 每字符位数 | 11 bit，1 start + 8 data + 1 parity + 1 stop |
| 功能码 | FC03 Read Holding Registers |
| 请求帧长度 | 8 byte |
| 读取 N 个寄存器响应帧长度 | `5 + 2N` byte |
| RTU 帧结束静默时间 | `t3.5` |

注意：表格是理论最短时间，不包含从站内部处理时间、RS-485 方向切换延迟、系统线程调度、日志打印耗时和总线冲突重试。

## 2. 计算公式

字符时间：

```text
char_time_ms = 11 / baudrate * 1000
```

Modbus RTU 帧结束静默时间：

```text
baudrate <= 19200: t3.5 = 3.5 * char_time
baudrate >  19200: t3.5 建议固定使用 1.75 ms
```

读取 N 个 Holding Register：

```text
request_bytes  = 8
response_bytes = 5 + 2N
serial_bytes   = request_bytes + response_bytes = 13 + 2N
```

主站从开始发送请求，到收到完整响应并等到 RTU 帧结束的理论最短等待时间：

```text
min_wait_ms = serial_bytes * char_time_ms + t3.5
```

如果要估算连续轮询周期，建议再加一个下一帧之前的 RTU 静默时间：

```text
min_poll_cycle_ms = min_wait_ms + t3.5
```

实际工程中建议：

```text
rx_timeout >= min_wait_ms + 从站处理时间 + 方向切换时间 + 调度余量
```

## 3. 读取 1 个寄存器

读取 1 个寄存器时：

| 帧 | 长度 |
| --- | --- |
| 请求帧 | 8 byte |
| 响应帧 | 7 byte |
| 总串口字节数 | 15 byte |

示例请求：

```text
01 03 00 00 00 01 84 0A
```

示例响应：

```text
01 03 02 12 34 B5 33
```

时间表：

| 波特率 | 字符时间 | t3.5 | 理论最短等待时间 | 连续轮询理论周期 |
| --- | ---: | ---: | ---: | ---: |
| 4800 | 2.292 ms | 8.021 ms | 42.396 ms | 50.417 ms |
| 9600 | 1.146 ms | 4.010 ms | 21.198 ms | 25.208 ms |
| 115200 | 0.095 ms | 1.750 ms | 3.182 ms | 4.932 ms |

结论：`9600 8E1` 读 1 个寄存器时，`20 ms` 的 `rx_timeout` 已经低于理论最短等待时间，容易出现“实际收到了响应，但 client 先超时”的现象。

## 8. Timeout 设置建议

建议不要直接使用理论最短时间作为 `rx_timeout`。实际工程可以按下面取值起步：

| 波特率 | 读取 1 到 2 个寄存器建议 `rx_timeout` | 说明 |
| --- | ---: | --- |
| 4800 | 100 ms 到 200 ms | 低速下帧本身已经很长 |
| 9600 | 100 ms 到 200 ms | 20 ms 太短，容易刚收到就已经超时 |
| 115200 | 20 ms 到 50 ms | 如果从站处理慢，继续加大 |

当前工程调试时建议先使用：

```c
#define MODBUS_ENCODER_RX_TIMEOUT_US 200000
```

等确认稳定后，再根据实际从站响应时间逐步收紧。

## 9. 8N1 时如何换算

如果设备使用 `8N1`，每字符是 10 bit，而不是 11 bit。粗略换算：

```text
8N1 串口传输时间 ~= 8E1 串口传输时间 * 10 / 11
```

但 Modbus RTU 标准在无校验时通常使用 2 个停止位，也就是 `8N2`，它同样是 11 bit。因此做 Modbus RTU 时间预算时，优先按 11 bit 每字符估算更稳妥。
