# 故障转储测试用例

## 1. 测试信息

- 警告：`faultdump test panic` 和 `faultdump test oops` 会主动制造故障，只能在测试固件和可恢复测试板执行。
- 工具：串口终端、复位/供电设备、必要的日志保存工具。

## 2. 用例

| 编号 | 内容 | 通过条件 |
|---|---|---|
| FAULT-001 | 查看初始状态 | 状态输出明确 |
| FAULT-002 | Oops 测试 | 记录可读且系统恢复 |
| FAULT-003 | Panic 测试 | 记录或 coredump 可获取 |
| FAULT-004 | 清除记录 | 两类记录按命令分别清除 |

### FAULT-001 查看初始状态
1. 上电后执行 `faultdump status`。
2. 执行 `faultdump record print`、`faultdump coredump status`。
3. 记录是否有简要记录、coredump 状态和 reset reason 内容。
4. 通过标准：命令有明确输出，初始状态与测试前记录一致。

### FAULT-002 记录 Oops（测试固件）
1. 确认已保存当前日志，并执行 `faultdump record clear`。
2. 执行 `faultdump test oops`，等待设备按设计复位或返回。
3. 重连串口，执行 `faultdump record print` 和 `faultdump status`。
4. 通过标准：记录包含本次故障类型和必要上下文；系统按设计恢复。

### FAULT-003 记录 Panic（测试固件）
1. 确认设备可重新烧录或复位恢复，执行 `faultdump record clear`。
2. 执行 `faultdump test panic`。
3. 重连后执行 `faultdump record print`、`faultdump coredump report`。
4. 若配置支持导出，执行 `faultdump coredump export` 并保存文件。
5. 通过标准：故障记录可读，coredump 状态与配置一致，无静默失败。

### FAULT-004 清除记录
1. 确认已有测试记录，执行 `faultdump record clear`。
2. 再执行 `faultdump record print`，确认简要记录已清除。
3. 执行 `faultdump coredump clear`，再执行 `faultdump coredump status`。
4. 通过标准：两类数据分别按命令清除，互不误清；状态输出明确。
