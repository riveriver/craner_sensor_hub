# Fault Dump 测试用例

实现：`module/fault_dump_service`。故障注入仅限专用测试构建或台架，不得在生产固件执行。

## 验收概览

| 编号 | 测试内容 | 验收标准 | 结果 |
| --- | --- | --- | --- |
| FD-001 | 无记录状态 | 无 Fault Dump 时状态准确 | |
| FD-002 | 故障记录 | 致命异常后记录可保存 | |
| FD-003 | 记录读取和导出 | 状态、摘要和完整数据格式正确 | |
| FD-004 | 重启原因 | 复位原因可区分并保留 | |
| FD-005 | 清除记录 | 清除后状态为空且设备可继续运行 | |
| FD-006 | 存储异常 | 分区异常时系统仍能启动并报告错误 | |

## 详细用例

### FD-001 无记录状态

1. 清理测试设备上的历史记录，或使用全新设备。
2. 查询 Fault Dump 状态。

预期：明确报告未发现有效记录，不因空分区阻塞启动。

### FD-002 故障记录

1. 使用测试构建触发一次受控 fatal/oops。
2. 设备重启后查询状态。

预期：记录存在，包含原因、时间/计数和有效长度；设备可正常完成启动。

### FD-003 记录读取和导出

1. 查询摘要。
2. 导出完整记录。
3. 检查 `#CD:BEGIN#`、数据行和 `#CD:END#` 边界。

预期：导出内容完整、顺序正确、无截断；MQTT 功能启用时发布内容符合配置 topic。

### FD-004 重启原因

1. 分别执行正常重启和受控故障复位。
2. 比对两次启动后的 reset reason。

预期：原因可区分，历史记录不会被无关正常启动覆盖。

### FD-005 清除记录

1. 确认测试允许删除历史数据。
2. 清除记录并再次查询。

预期：状态为空，设备继续响应网络和协议请求。

### FD-006 存储异常

1. 使用规定的异常存储夹具或配置模拟不可用分区。
2. 重启并查询状态。

预期：启动不被阻塞，报告可诊断错误；不得误报有效 Fault Dump。

## 缺陷证据

附故障注入方式、复位时间、reset reason、状态输出、导出原文和设备版本。
