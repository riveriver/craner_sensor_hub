# 固件升级测试用例

## 1. 测试信息

- 目的：验证合法升级、重启切换、失败保护和版本确认。
- 开发人员填写：升级工具/服务器 ______；有效镜像 ______；目标版本 ______；回滚能力 ______。
- 升级前保存 `id show`、`param list`、`param status`、`net iface` 输出和当前固件版本。

## 2. 用例

| 编号 | 内容 | 通过条件 |
|---|---|---|
| OTA-001 | 有效镜像升级 | 版本切换且设备可用 |
| OTA-002 | 升级中断恢复 | 不进入不可恢复状态 |
| OTA-003 | 无效镜像拒绝 | 当前固件不被破坏 |
| OTA-004 | 升级后确认 | 重启后版本和业务正常 |

### OTA-001 有效镜像升级
1. 确认设备供电稳定、网络可用，记录当前版本和参数。
2. 使用项目规定的 `mcumgr` 或升级工具上传有效镜像，记录进度和耗时。
3. 按流程重启，等待设备重新上线。
4. 检查版本、`id show`、`param list`、网络和业务功能。
5. 通过标准：版本切换成功，设备可用，参数和身份符合设计。

### OTA-002 升级中断恢复
1. 开始上传有效镜像，在 ______% 时断开网络或停止工具。
2. 恢复网络后按项目流程继续或重新上传。
3. 通过标准：设备不会进入不可恢复状态；失败时仍能启动旧版本或按设计恢复。

### OTA-003 无效镜像拒绝
1. 分别准备错误签名、错误硬件目标、损坏或版本不允许的镜像。
2. 尝试上传并记录工具返回值和设备行为。
3. 通过标准：镜像被拒绝，当前可启动固件和参数不被破坏。

### OTA-004 升级后确认
1. 升级完成后断电再上电一次。
2. 重复检查版本、网络、Shell、参数、传感器和 Modbus/MQTT。
3. 通过标准：升级状态已确认，不反复回滚或重复升级。
