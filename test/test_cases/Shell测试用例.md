# Shell测试用例

## 1. 测试信息

- 支持串口和 MQTT Shell。MQTT 默认使用 Zephyr 硬件短 ID：例如 `363838/sh/rx` 接收、`363838/sh/tx` 发布。
- 工具：串口终端、MQTT 客户端。服务器地址、端口、账号按项目配置填写：________。
- MQTT Shell 只回传 Shell 命令结果；正常业务日志不应大量进入 `/sh/tx`。

## 2. 用例

| 编号 | 内容 | 通过条件 |
|---|---|---|
| SHELL-001 | 串口基础命令 | 命令可响应 |
| SHELL-002 | MQTT 收发 | 主题、QoS 和响应正确 |
| SHELL-003 | 参数和故障命令 | 两种后端结果一致 |
| SHELL-004 | 无效输入 | 明确报错且不中断 |
| SHELL-005 | 日志隔离 | 普通日志不刷 Shell 主题 |
| SHELL-006 | 断线重连 | MQTT Shell 可恢复 |

### SHELL-001 串口基础命令
1. 串口连接后执行 `id show`、`param status`、`param list`。
2. 保存完整回显，确认命令提示符和响应可读。
3. 通过标准：命令有响应，无乱码、死锁或异常复位。

### SHELL-002 MQTT 收发
1. 使用 MQTT 客户端订阅 `<short_id>/sh/tx`，发布命令到 `<short_id>/sh/rx`，QoS 使用项目配置 ______。
2. 发布 `id show` 和 `param status`，记录主题、QoS、响应延迟和响应内容。
3. 通过标准：响应只发布到 `/sh/tx`，主题短 ID 与设备身份一致。

### SHELL-003 参数和故障命令
1. 通过串口执行 `param list`、`faultdump status`、`faultdump record print`。
2. 通过 MQTT 重复执行相同命令，比较输出内容。
3. 通过标准：两种后端执行结果一致；危险命令仅在测试固件按专门用例执行。

### SHELL-004 无效输入
1. 发送空消息、未知命令、超长命令和不完整参数。
2. 记录错误提示、连接状态和设备日志。
3. 通过标准：给出明确错误，不崩溃、不阻塞后续命令。

### SHELL-005 日志隔离
1. 订阅 `<short_id>/sh/tx`，同时运行正常 Modbus、传感器和网络业务 ______ min。
2. 记录 `/sh/tx` 消息数量和内容；Shell 执行一次 `id show` 作对照。
3. 通过标准：`/sh/tx` 主要包含 Shell 请求的响应，不因普通业务日志产生大量消息。

### SHELL-006 断线重连
1. 建立 MQTT Shell 后断开客户端或网络 ______ s，再恢复。
2. 重新订阅主题并发送 `id show`。
3. 通过标准：设备和 MQTT Shell 恢复，未出现重复连接或资源泄漏。
