# 系统健康测试用例

实现：`app/system_health`、`module/system_health_service`。重点验证设备不会因单一模块异常而卡死，并能执行健康保护策略。

## 验收概览

| 编号 | 测试内容 | 验收标准 | 结果 |
| --- | --- | --- | --- |
| HLT-001 | 正常健康状态 | 各已启用事件保持在线 | |
| HLT-002 | 采样超时 | 事件离线、记录日志并进入预期状态 | |
| HLT-003 | 事件恢复 | 恢复后状态回 online 并记录时长 | |
| HLT-004 | 看门狗保护 | 线程异常时设备按配置复位 | |
| HLT-005 | 网络探测 | 网关探测失败触发降级而非死循环 | |
| HLT-006 | 长时间运行 | 连续运行无异常复位、堆栈溢出或卡死 | |

## 详细用例

### HLT-001 正常健康状态

1. 接入已配置的传感器并启动设备。
2. 连续观察至少 10 分钟健康状态和日志。

预期：已启用事件持续被报告，无误报离线，设备可响应维护和 Modbus 请求。

### HLT-002 采样超时

1. 在允许的台架条件下停止一个传感器响应。
2. 等待超过该事件的 offline timeout。

预期：只影响对应事件；产生一次离线记录并执行配置的降级/看门狗动作。

### HLT-003 事件恢复

1. 恢复传感器响应。
2. 观察恢复事件和状态。

预期：事件恢复为 online，offline duration、recover count 等统计合理。

### HLT-004 看门狗保护

1. 使用专用故障注入构建或测试夹具使健康喂狗条件失效。
2. 记录设备是否在配置时间内复位。

预期：设备复位后能正常启动；生产构建不得暴露危险的故障注入入口。

### HLT-005 网络探测

1. 在启用 ICMP 探测时阻断网关响应。
2. 观察健康状态、日志和设备可维护性。

预期：状态进入降级或离线，网络恢复后可恢复；不会因探测失败阻塞主流程。

### HLT-006 长时间运行

1. 设备连续运行 24 小时。
2. 每小时检查一次网络、采样、健康和协议访问。

预期：无无故复位、卡死、明显内存增长或线程堆栈异常。

## 缺陷证据

附健康事件名称、首次离线/恢复时间、日志、复位原因、运行时长和测试期间的操作记录。
