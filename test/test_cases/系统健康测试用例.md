# 系统健康测试用例

## 1. 测试信息

- 目的：确认设备长期运行可观测、异常可恢复、任务不会永久阻塞。
- 前置：记录固件版本和上电时间；开发人员填写健康状态命令/阈值 ______、允许恢复时间 ______ s。
- 工具：串口终端、稳定电源、网络工具、必要的传感器/RS485 模拟设备。

## 2. 用例

| 编号 | 内容 | 通过条件 |
|---|---|---|
| HEALTH-001 | 上电基线 | 服务初始化完成 |
| HEALTH-002 | 资源和任务稳定性 | 无泄漏、无永久超时 |
| HEALTH-003 | 外设不可用恢复 | 故障可记录且可恢复 |
| HEALTH-004 | 长时间业务运行 | 无异常复位和失联 |

### HEALTH-001 上电基线
1. 上电后等待系统初始化完成。
2. 执行 `id show`、`param status`、`net iface`、`faultdump status` 和 `faultdump record print`。
3. 记录接口状态、参数状态、故障记录、异常日志和复位原因（若记录中包含）。
4. 通过标准：服务初始化完成；无未解释故障；网络状态符合现场配置。

### HEALTH-002 资源和任务稳定性
1. 在空闲状态和正常业务状态分别观察 ______ min。
2. 按项目提供的健康观测方式记录线程、堆、栈、队列或错误计数。
3. 通过标准：资源不持续泄漏；关键任务无反复超时；设备持续响应 Shell 和业务请求。

### HEALTH-003 外设暂时不可用恢复
1. 在安全条件下断开一个非关键传感器或 RS485 从站。
2. 等待 ______ min，观察日志和设备响应；恢复连接后再次观察 ______ min。
3. 通过标准：异常被记录但不导致系统卡死；外设恢复后业务自动恢复或给出明确重试状态。

### HEALTH-004 长时间业务运行
1. 同时运行网络、Modbus、传感器采样和参数读取等正常业务 ______ h。
2. 每小时执行一次 `net iface`、`param status`、`faultdump status`，记录结果。
3. 通过标准：无异常复位、无持续错误增长、Shell 可响应、业务数据持续更新。
