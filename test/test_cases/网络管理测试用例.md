# 网络管理测试用例

实现：`module/network_manager_service`。网络诊断与统计包含在本功能域中。

## 前置条件

准备可用以太网交换机、DHCP 服务、测试 PC，并记录 hostname、IP、MAC 和 DHCP 租约参数。

## 验收概览

| 编号 | 测试内容 | 验收标准 | 结果 |
| --- | --- | --- | --- |
| NET-001 | 链路启动 | 网线接入后链路和 IPv4 状态正确 | |
| NET-002 | DHCP 获取地址 | 获取合法 IP、网关和租约信息 | |
| NET-003 | 断网恢复 | 断线后状态变化，恢复后重新 ready | |
| NET-004 | DHCP 异常重试 | DHCP 不可用时不死机并按策略重试 | |
| NET-005 | 网络统计 | 连接、事件、错误和重试统计可查询 | |

## 详细用例

### NET-001 链路启动

1. 上电并接入交换机。
2. 观察设备是否出现链路事件并获取 IPv4 地址。
3. 从 PC 执行 `ping <device-ip>`，再连接 Telnet。

预期：设备启动不阻塞；链路状态、IP、网关和 ready 状态一致。

### NET-002 DHCP 获取地址

1. 启动 DHCP 服务并重启设备。
2. 记录分配的 IP、掩码、网关、DHCP server 和 lease。
3. 与交换机/DHCP 日志比对。

预期：地址字段完整且与 DHCP 记录一致，重复重启不会产生非法或空 MAC。

### NET-003 断网恢复

1. 设备 ready 后拔出网线，记录状态变化。
2. 等待 10 秒后重新接入网线。
3. 重复 ping 和 Telnet 测试。

预期：断网期间不崩溃；恢复后重新获取地址或恢复 ready，统计中有对应事件。

### NET-004 DHCP 异常重试

1. 关闭 DHCP 服务后重启设备。
2. 观察 2 个重试周期。
3. 恢复 DHCP，确认设备最终 ready。

预期：设备保持可运行，状态为等待或失败而非误报 ready；恢复后可重新初始化。

### NET-005 网络统计

1. 通过已提供的诊断入口读取网络状态和统计。
2. 完成一次断网/恢复，再次读取。

预期：统计字段可解析，计数变化与实际事件数量一致，清零操作仅在明确允许时执行。

## 缺陷证据

附 hostname/IP、时间、固件版本、网络拓扑、DHCP 日志、Telnet 输出和必要的 Wireshark 报文。
