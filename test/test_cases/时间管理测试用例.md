# 时间管理测试用例

实现：`module/time_manager_service`。测试人员只使用设备 Shell 和测试 PC。

## 前置输入

填写 NTP 地址、时区、允许误差、RTC 是否启用和测试 PC 当前时间。

## 验收概览

| 编号 | 测试内容 | 验收标准 | 结果 |
| --- | --- | --- | --- |
| TIM-001 | 启动时间状态 | 无有效时间源时状态明确 | |
| TIM-002 | NTP 同步 | 网络恢复后时间同步到阈值内 | |
| TIM-003 | RTC 重启恢复 | 重启后时间连续且误差可接受 | |
| TIM-004 | 异常服务器恢复 | NTP 异常不阻塞，恢复后可重试 | |

## 详细用例

### TIM-001 启动时间状态

1. 在无网络或无有效时间源条件下上电。
2. 执行项目发布版本规定的时间查询命令，记录时间和状态。

预期：状态明确标识未同步/低可信，不显示伪造的已同步状态，设备仍能运行。

### TIM-002 NTP 同步

1. 接入可用网络和 NTP 服务。
2. 重启设备，按 10 秒间隔查询时间状态，最多等待 120 秒。
3. 用测试 PC 记录同步时刻并比较时间差。

预期：时间源状态变为同步/有效，误差不超过发布阈值；同步失败时应有明确状态。

### TIM-003 RTC 重启恢复

1. 完成一次 NTP 同步并记录时间。
2. 断电 30 秒后重新上电。
3. 查询时间和时间源状态。

预期：RTC 时间单调前进，重启后误差在发布阈值内；网络恢复后可再次 NTP 校时。

### TIM-004 异常服务器恢复

1. 配置不可达的 NTP 服务，重启并等待 3 个重试周期。
2. 确认设备仍可执行其他 Shell 命令。
3. 恢复正确 NTP 服务并等待同步。

预期：时间服务不阻塞主业务；重试状态清晰；服务恢复后同步成功。
