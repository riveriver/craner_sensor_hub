# Modbus TCP 测试用例

实现：`module/modbus_tcp_server`、`module/modbus_data_model`、`app/modbus_tcp/modbus_register_app.c`。

## 前置条件

使用 OpenModScan 或同类工具。默认连接参数需由发布配置确认：服务器 IP、端口（通常 502）、Unit ID（通常 1）和地址基准。本文使用协议 0-based 地址，若工具为 1-based，需按工具规则换算。

## 详细用例

### MBTCP-001 TCP 建连

1. 连接设备网络。
2. 使用 Unit ID 和端口配置建立 Modbus TCP 连接。
3. 连续读取一个已知输入寄存器。

预期：连接成功，响应 transaction ID、Unit ID 和 PDU 正确。

### MBTCP-002 输入寄存器读取

1. 按发布寄存器表读取版本、设备能力和传感器状态区域。
2. 将协议响应与 Shell/日志或传感器实际状态比对。

预期：地址、数量、字节序、默认值和实时值一致。

### MBTCP-003 Coil 读写

1. 读取 coil 有效地址。
2. 写入 0 和 1，再次读取。
3. 访问只读或无效 coil。

预期：合法访问成功；越权访问返回对应异常码。

### MBTCP-004 Holding 读写

1. 读取 holding 有效地址。
2. 写入边界值和正常值，再次读取。
3. 访问未定义地址。

预期：只允许发布表声明的读写操作，未定义地址不会越界。

### MBTCP-005 非法地址/功能码

1. 发送越界地址、零数量、超长数量和不支持功能码请求。

预期：返回标准 Modbus exception response，服务线程继续响应正常请求。

### MBTCP-006 多客户端

1. 同时建立配置允许的最大客户端数。
2. 再建立一个额外客户端并持续发送请求。

预期：达到上限时按配置拒绝或关闭额外连接；已有客户端不互相污染。

### MBTCP-007 超时和断线恢复

1. 建立连接后保持空闲超过 idle timeout，或直接拔掉客户端网络。
2. 重新建立连接并读取寄存器。

预期：旧 socket 被释放，新客户端可连接，服务不死锁。

### MBTCP-008 持久化寄存器

1. 写入 persistent holding register。
2. 等待自动保存或执行发布配置允许的保存动作。
3. 重启并读取。

预期：写入值恢复；非 persistent 寄存器不应被错误保存。

## 缺陷证据

附工具版本、服务器 IP/端口、Unit ID、地址模式、功能码、地址、数量、原始响应和截图。
