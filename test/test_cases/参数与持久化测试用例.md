# 参数与持久化测试用例

实现：`module/device_param_server`、`module/modbus_data_model`。存储后端是可选能力，测试必须先确认本产品是否启用以及实际分区位置。

## 验收概览

| 编号 | 测试内容 | 验收标准 | 结果 |
| --- | --- | --- | --- |
| PAR-001 | 默认参数 | 首次启动加载正确默认值 | |
| PAR-002 | 参数修改 | 合法值可设置，非法值被拒绝 | |
| PAR-003 | 保存与重启恢复 | 保存值重启后保持 | |
| PAR-004 | 未保存值 | 未执行保存时重启不持久化 | |
| PAR-005 | 恢复默认 | 恢复默认后值和状态正确 | |
| PAR-006 | 数据模型持久化 | 仅标记 persistent 的寄存器被保存 | |
| PAR-007 | 无存储后端 | 存储关闭时核心数据模型仍可用 | |

## 详细用例

### PAR-001 默认参数

1. 使用清空参数区的设备启动。
2. 查询参数状态和发布的默认参数表。

预期：默认值正确，加载失败不会阻塞系统启动。

### PAR-002 参数修改

1. 对每个可测试参数设置一个合法值。
2. 分别设置越界、错误类型、空值和过长字符串。

预期：合法值更新 RAM 镜像并标记 dirty；非法值返回明确错误且原值不变。

### PAR-003 保存与重启恢复

1. 设置参数并执行保存。
2. 断电/重启后再次读取。

预期：保存值恢复，状态显示加载成功且无重复写入异常。

### PAR-004 未保存值

1. 设置新值但不执行保存。
2. 重启并读取参数。

预期：恢复上一次已保存值，未保存 RAM 值不应伪持久化。

### PAR-005 恢复默认

1. 确认允许清除数据。
2. 执行参数恢复默认操作并重启。

预期：所有参数回到发布默认值，状态和输出格式一致。

### PAR-006 数据模型持久化

1. 写入一个 persistent holding register 和一个非 persistent register。
2. 执行保存并重启。

预期：只有 persistent 寄存器恢复写入值，其他寄存器使用默认值。

### PAR-007 无存储后端

1. 使用关闭存储后端的测试配置启动。
2. 读取、写入和访问数据模型。

预期：核心读写功能可用；持久化操作返回能力未启用或等价明确结果，不得崩溃。

## 缺陷证据

附参数名、设置前后值、保存操作、重启时间、状态输出和是否启用存储后端。
