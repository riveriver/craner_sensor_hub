# 参数与持久化测试用例

## 1. 测试范围

本文件用于验证设备参数服务的查询、修改、保存、重启恢复和恢复默认功能。测试对象是设备身份参数：

```text
id.company
id.model
id.product
```

Modbus 数据模型寄存器的持久化属于 Modbus TCP 测试专项，本文件不要求测试人员执行 Modbus 写寄存器操作。

## 2. 测试工具与输入

| 项目 | 测试要求 |
| --- | --- |
| 设备连接 | 设备已上电并接入以太网 |
| Shell 工具 | MobaXterm Telnet 或 MQTTX |
| Telnet | 设备 IP 或 hostname，端口 23 |
| MQTT Broker | `mqtt.craner.hk:1883`，以测试组实际账号为准 |
| MQTT Shell RX | `<short_id>/sh/rx` |
| MQTT Shell TX | `<short_id>/sh/tx` |
| 重启方式 | 使用现场允许的断电重启或 `reboot` 命令 |
| 清除权限 | 执行 `param factory_reset` 前必须获得测试负责人确认 |
| 产品默认值 | 由发布配置或测试负责人填写，不要凭经验填写 |

建议测试值：

| 参数 | 测试值 |
| --- | --- |
| `id.company` | `test-company` |
| `id.model` | `test-model` |
| `id.product` | `test-product` |

## 3. 连接方式

### 3.1 Telnet Shell

1. 使用 MobaXterm 新建 Telnet 连接。
2. 填写设备 IP 或 hostname，端口填写 `23`。
3. 连接成功后，在终端中输入 Shell 命令并记录完整输出。

### 3.2 MQTT Shell

1. 使用串口或现场设备标签先获得 `short_id`。
2. 在 MQTTX 中连接测试 Broker。
3. 订阅 `<short_id>/sh/tx`。
4. 向 `<short_id>/sh/rx` 发布命令。
5. 每条命令必须等待对应的 TX 响应后再发送下一条。

本文中的命令示例使用 Telnet 表示；通过 MQTT 执行时只需将命令文本作为 payload 发布。

## 4. 结果状态

- `通过`：实际结果符合预期。
- `失败`：实际结果与预期不符，必须填写缺陷编号。
- `阻塞`：设备、网络、账号、权限或工具问题导致无法执行。
- `不适用`：当前产品明确未启用对应能力。

## 6. 详细测试用例

### PAR-001 参数服务状态与参数清单

1. 连接设备 Shell。
2. 执行：

   ```text
   param status
   param list
   ```

3. 记录完整输出。

预期结果：

- `initialized=yes`。
- `param_count=3`。
- `param list` 包含 `id.company`、`id.model`、`id.product`。
- 如果 `settings_ready=no`，将本用例标记为 `失败` 或 `阻塞`，并继续执行 PAR-007，不得直接忽略。

### PAR-002 默认参数验证

1. 确认测试负责人允许清除参数。
2. 执行：

   ```text
   param factory_reset
   ```

3. 等待命令返回成功，再重启设备。
4. 重启完成后执行：

   ```text
   param list
   id show
   ```

预期结果：3 个 `id.*` 参数恢复产品默认值；`id show` 中的身份字段与参数列表一致；设备正常启动。

### PAR-003 参数修改与校验

1. 先执行 PAR-002，确保设备处于默认状态。
2. 依次执行：

   ```text
   param set id.company test-company
   param set id.model test-model
   param set id.product test-product
   ```

3. 执行：

   ```text
   param list
   param status
   ```

4. 分别测试非法值：

   ```text
   param set id.company ""
   param set id.model "test model"
   param set id.product "test/product"
   ```

预期结果：

- 合法值设置成功并显示 `dirty=yes`。
- `param list` 显示 3 个测试值。
- 空值、带空格值和带 `/` 的值被拒绝。
- 非法值被拒绝后，原来的合法值不变。
- 修改参数不会导致设备重启或业务停止。

恢复步骤：执行 `param factory_reset`，然后重启设备。

### PAR-004 保存与重启恢复

1. 先执行 PAR-002。
2. 执行 PAR-003 中的 3 条合法设置命令。
3. 执行：

   ```text
   param status
   param save
   ```

4. 记录 `param save` 的完整返回内容。
5. 保存成功后重启设备。
6. 重启完成后执行：

   ```text
   param status
   param list
   id show
   ```

预期结果：

- 保存成功返回 `status=ok`。
- 保存后 `dirty=no`。
- 重启后 3 个参数仍为测试值。
- `id show` 中身份字段与参数一致。

异常处理：如果 `settings_ready=no` 或保存返回错误，停止本用例的重启验证，转到 PAR-007 并保留完整输出。

恢复步骤：执行 `param factory_reset`，然后重启设备。

### PAR-005 未保存值验证

1. 先执行 PAR-002，确保设备恢复产品默认值。
2. 设置 3 个测试值，但不执行 `param save`。
3. 确认 `param status` 显示 `dirty=yes`。
4. 直接重启设备。
5. 重启完成后执行 `param list` 和 `id show`。

预期结果：未保存的测试值不会被保留；参数恢复为上一次成功保存的值，首次执行时应为产品默认值；设备不会卡死。

恢复步骤：执行 `param factory_reset`，然后重启设备。

### PAR-006 恢复出厂参数

1. 先执行 PAR-003 设置 3 个测试值。
2. 如需验证已保存数据，执行 `param save` 并确认返回 `status=ok`。
3. 确认测试负责人允许删除持久化数据。
4. 执行：

   ```text
   param factory_reset
   ```

5. 记录命令返回，重启设备。
6. 重启后执行：

   ```text
   param status
   param list
   id show
   ```

预期结果：恢复出厂命令成功；3 个 `id.*` 参数恢复产品默认值；`dirty=no`；设备正常启动。

### PAR-007 持久化异常提示

1. 执行：

   ```text
   param status
   ```

2. 如果输出为 `settings_ready=no`，记录 `last_error`。
3. 如果当前有脏参数，执行：

   ```text
   param save
   ```

4. 记录完整错误输出。

预期结果：

- 保存失败时同时返回错误码和人类可读原因，例如：

  ```text
  save failed: -11 (settings backend is not ready)
  ```

- `param status` 中的 `dirty=yes` 与实际状态一致。
- 保存失败不能导致设备崩溃或卡死。
